## Slide 2: The WiFi Intelligence Challenge

### The "Strong Signal, Poor Performance" Paradox

**Real-World Scenario:**
User has WNC Mesh with full signal bars everywhere, but experiences:
- Slow speeds and buffering
- Poor performance despite "strong signal"
- Works great when wired directly to router

**Root Causes (Complex WiFi-Specific Issues):**
1. **Inefficient Backhaul**: Wireless backhaul between nodes is bottleneck (distance, congestion, obstructions)
2. **Sticky Clients**: Devices refuse to roam to better nodes despite availability
3. **Poor Band/Node Steering**: System makes suboptimal decisions (2.4 GHz vs. 5 GHz, overloaded nodes)
4. **Co-Channel Interference**: Multiple WiFi networks competing in dense environments

**Why WiFi Mesh Needs Domain-Specific Intelligence:**

| Generic Network Monitoring | WNC MeshLog WiFi Intelligence |
|---------------------------|---------------------------|
| Detects "anomaly" | Understands "client steering loop" |
| Alerts on high CPU | Explains "excessive channel scanning due to DFS" |
| Reports connectivity loss | Diagnoses "802.11v BTM rejection - incompatible IE" |
| Shows traffic patterns | Interprets "sticky client refusing optimal roaming" |
| Reactive to symptoms | **Demonstrates WNC SON solving these problems** |

**The WNC SON Solution Being Validated:**
- Dynamic backhaul path selection (wireless/Ethernet awareness)
- Proactive client steering (802.11k/v/r standards)
- Intelligent band and load balancing
- Adaptive RRM for interference mitigation

**MeshLog's Dual Role:**
1. **Quality Demonstration**: Prove WNC SON features are working correctly
2. **Expert Troubleshooting**: Diagnose when something isn't working and why
